## 项目整体分析（toutiao_backend）

通读全项目（约 3500 行 Python，35 个文件），产出架构分析与问题清单。

### 项目实际构成
- 名字叫 toutiao_backend，实为两个互不相干系统共用一个 FastAPI app：
  1. 新闻 + 用户 CRUD（routers/news.py、users.py、crud/、models/，SQLAlchemy 异步 + MySQL）
  2. travel_agent 旅行规划 Agent（LangGraph ReAct + DeepSeek + 9 个工具 + 高德/Open-Meteo）
- 两者无业务关联，仅共享 main.py 挂载。

### 发现的关键问题（未修复，仅分析）
- **requirements.txt 严重缺失**：无 fastapi / uvicorn / sqlalchemy / aiomysql / passlib / requests / langgraph；langchain 版本与注释矛盾（3.1.3 vs 1.2.7）。
- **utils/auth.py 三重 bug**：`Depends(get_db())` 多括号；`from sqlalchemy.sql.functions import user` 导致 `if not user` 恒假；`get_user_by_token` 返回值未赋值。认证形同虚设（/api/user/info 已注释，暂未暴露）。
- **两套重复 Settings**：config/settings.py 与 travel_agent/config.py 内容几乎一致。
- **history.py 的 build_history_context / save_preference 是死代码**，从未被调用 → planner 的天气与历史偏好功能实际未生效（plan_trip 只传 preference）。
- **PII 脱敏不闭环**：只挂在 agent.py 的 ChatOpenAI 上，extractor/planner/scorer 各自 new 的 LLM 都没有 callback，且无还原映射。
- **extractor.py `_invoke_llm` 降级链**：except 块引用可能未定义的 `response`，会 UnboundLocalError。
- **profile / history 存全局单文件**（data/user_profile.json），多用户互相污染；路径用相对 "data"，依赖 CWD。
- **travel chat 是同步 def**，agent.invoke 阻塞 event loop。
- **models/news.py 与 models/users.py 各自定义 DeclarativeBase** → metadata 分裂；全项目无 create_all / Alembic 建表。
- 无测试、无 README、无 Dockerfile、无日志与全局异常处理。
- CORS `allow_origins=["*"]` + `allow_credentials=True` 组合无效且有风险。
